# v0.4.0

Released: 2026-08-13

## English

### Highlights

- `plan-tree install claude|opencode|codex|all` now installs a concise persistent Plan Tree instruction for each selected provider by default. Claude Code uses `~/.claude/CLAUDE.md`, OpenCode uses `~/.config/opencode/AGENTS.md`, and Codex uses `$CODEX_HOME/AGENTS.md`.
- Instruction updates are marker-bounded and idempotent. Existing user content and file permissions are preserved, and upgrades replace only the managed Plan Tree block.
- New Plan Tree guidance adds stable Plan IDs such as `P001` with flat `plans/001-<name>/` directories, optional roadmap-owned task IDs, and affected-module metadata without physical module nesting.

### Fixes and reliability

- Both the npm and Python installers now share regression coverage for every provider, including preservation, repeated installation, malformed-marker rejection, dry-run behavior, opt-out behavior, and custom skill targets.
- Release publication now validates the tag, synchronized version surfaces, tests, and bilingual notes before creating the GitHub Release. npm and PyPI publication follow as staged registry jobs; npm uses Trusted Publishing through OpenID Connect (OIDC) instead of a long-lived token.

### Upgrade notes

- Upgrade the installer with `npm install -g plan-tree@0.4.0` or `python -m pip install --upgrade seemseam-plan-tree==0.4.0`, then run `plan-tree install <provider> --force` to update an existing skill installation.
- Provider instructions are installed by default. Use `--no-instructions` to leave the provider instruction file unchanged, or `--dry-run` to inspect both targets without writing.
- No Plan Tree migration is required. Existing unnumbered or mature trees remain valid and may adopt the lightweight numbering convention gradually.

### Known limitations

- Provider instruction files are persistent behavioral context, not replacements for the provider's built-in system prompt and not a security enforcement mechanism.
- A malformed or duplicated Plan Tree marker block must be repaired manually before installation; the installer intentionally refuses ambiguous automatic repair.
- npm and PyPI availability may temporarily lag behind the GitHub Release while registry Trusted Publishing authorization is completed. Verify the registry version before using the upgrade commands above.

## 中文

### 版本亮点

- `plan-tree install claude|opencode|codex|all` 现在会默认为所选 Provider 安装一段精简的 Plan Tree 持久指令。Claude Code 写入 `~/.claude/CLAUDE.md`，OpenCode 写入 `~/.config/opencode/AGENTS.md`，Codex 写入 `$CODEX_HOME/AGENTS.md`。
- 指令更新使用明确 marker，支持幂等升级。安装器会保留用户原有内容和文件权限，升级时只替换 Plan Tree 管理区块。
- 新的 Plan Tree 规则支持 `P001` 等稳定 Plan 编号及平铺的 `plans/001-<name>/` 目录，并允许使用仅由 roadmap 管理的可选任务编号和模块影响元数据，无需建立物理模块目录层。

### 修复与稳定性

- npm 与 Python 安装器现在对所有 Provider 运行一致的回归测试，覆盖用户内容保护、重复安装、异常 marker 拒绝、dry-run、退出注入和自定义 skill 目标。
- 发布流程会先校验 tag、版本一致性、测试和双语发布说明，然后创建 GitHub Release。npm 与 PyPI 作为后续分阶段 registry 任务发布；npm 改用基于 OpenID Connect（OIDC）的 Trusted Publishing，不再依赖长期 token。

### 升级说明

- 使用 `npm install -g plan-tree@0.4.0` 或 `python -m pip install --upgrade seemseam-plan-tree==0.4.0` 升级 installer，然后运行 `plan-tree install <provider> --force` 更新已有 skill。
- 默认会安装 Provider 持久指令。使用 `--no-instructions` 可保持 Provider 指令文件不变；使用 `--dry-run` 可只查看 skill 和指令目标而不写入。
- 无需迁移现有 Plan Tree。未编号或已有成熟约定的规划树仍然有效，可以逐步采用轻量编号规则。

### 已知限制

- Provider 指令文件属于每次会话加载的行为上下文，不会替换 Provider 内置 system prompt，也不是安全强制机制。
- 如果 Plan Tree marker 缺失、重复或顺序异常，必须先手工修复；安装器会拒绝有歧义的自动修复。
- 在 registry Trusted Publishing 授权完成前，npm 与 PyPI 的可用时间可能暂时晚于 GitHub Release。执行上述升级命令前，请先确认 registry 中已经存在对应版本。
